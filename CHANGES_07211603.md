## Part 1 — Recorder wired into the execution path

### 1a. Turn context (`agent/interp/session_recorder.py`)

Added a process-local `contextvars.ContextVar` for the "current turn":
`set_current_turn_id` / `get_current_turn_id` / `clear_current_turn_id`.
Also added `SessionRecorder.next_call_order(turn_id)` (base returns `0`;
`ActiveRecorder` increments a per-turn counter under `_TurnState.lock`) so
concurrent sub-agents sharing a turn get a monotonic, thread-safe
`call_order`.

### 1b. Turn start/end (`run_agent.py`)

`AIAgent.run_conversation` (the forwarder to
`agent.conversation_loop.run_conversation`) now owns the profiling turn
lifecycle:

- If no turn is already active on the current thread
  (`get_current_turn_id()` is empty), it generates `turn_id = uuid4().hex`,
  calls `get_recorder().start_turn(...)` with the HF-local model id/config
  read from `hermes_cli.config.load_config()["hf_local"]`, and binds it via
  `set_current_turn_id`.
- A nested call (a sub-agent's `run_conversation`, once its turn id has been
  propagated — see 1d below) sees an already-set turn id and does *not*
  start a new turn; it just rides the ambient one.
- `complete_turn` / `clear_current_turn_id` run in a `finally` so they fire
  on both normal return and exceptions, only for the call that owns the
  turn.

This is a no-op path when `profiling.enabled=false` (`get_recorder()`
returns `NoOpRecorder`) and never imports torch/transformers.

### 1c. Per-call `InferenceRecord`s

- **`agent/agent_init.py`** — `_HFLocalClientShim` now takes the owning
  `agent` reference. `_Completions.create()` builds a shared `meta` dict
  (`request_id`, `call_order` via `next_call_order`, `parallel_group`,
  `is_parallel`, `tool=""`, `model`) that's passed into
  `pool.generate(..., meta=meta)` *and* reused to build the
  `InferenceRecord` afterward, so probe rows and the record carry identical
  identifiers. `role` is `"subagent"` when `agent._subagent_id` is set,
  else `"main"`. `input_delta` is tracked via a per-shim
  `_last_msg_count`, diffed against the incoming `messages` list (reset to
  0 if the list shrank, e.g. after compression). `tools_called` reuses
  `agent.transports.hf_local._parse_tool_calls` instead of duplicating the
  `<tool_call>` regex.
- **`agent/auxiliary_client.py`** — `_call_hf_local_aux()` does the same for
  the aux path: `role="aux"`, `tool=<task name>`, `parallel_group=""`,
  `is_parallel=False`. Since aux calls are one-shot, `input_delta` is the
  full `messages` list for that call (no cross-call state to diff against).

Both call `get_recorder().add_record(...)` unconditionally — cheap
(`NoOpRecorder.add_record` is a true no-op) and correct even when the turn
id is empty (`ActiveRecorder.add_record` silently drops records for unknown
turn ids).

### 1d. Completion barrier & thread propagation (`tools/delegate_tool.py`)

- `delegate_task()` captures `_parent_turn_id = get_current_turn_id()` on
  its own thread, *before* anything hands off to a background/executor
  thread — contextvars aren't inherited by new threads, so this has to be
  read on the correct thread up front and threaded through explicitly.
- Children of a multi-task batch (`n_tasks > 1`) are stamped with
  `child._hf_parallel_group` (a fresh uuid per batch) and
  `child._hf_is_parallel = True`, read by the shim when building each
  child's `InferenceRecord`.
- `_execute_and_aggregate()` calls `register_pending(_parent_turn_id,
  count=n_tasks)` once before running any child (covers both the
  single-task direct-call path and the `DaemonThreadPoolExecutor` batch
  path).
- `_run_single_child()` takes a new `parent_turn_id` parameter; its
  `finally` block calls `complete_pending(parent_turn_id, 1)` unconditionally
  (success, error, or timeout).
- Inside `_run_single_child`'s own timeout-capture executor
  (`_run_with_thread_capture`, which runs `child.run_conversation` on a
  fresh thread), `set_current_turn_id(parent_turn_id)` is called first —
  this is the actual cross-thread propagation the parent's turn id needs so
  the child's HF calls attach to the *parent's* turn instead of opening
  their own.

Net effect: a parent turn with in-flight children/aux calls won't flush
until every registered pending completion reports in, so all
InferenceRecords for one user turn land in a single json/csv pair.

### 1e. Layer inventory — skipped

Left `set_layer_inventory` unwired (the `.txt` report's "Layer Inventory"
section stays empty). The brief explicitly allows skipping this if the
worker→parent IPC plumbing is large — `_write_txt` already handles an empty
`layer_inventory` list gracefully, so nothing breaks.

## Part 2 — Decode probe actually runs

### 2a. Capture no longer overwrites (`agent/hf_local/capture.py`)

`generate()` triggers one forward per prefill + one per decode step; the
old hook did `storage[layer_idx] = data`, so only the **last** decode
step's capture survived generation — meaning even the *prefill* probe was
silently pairing the wrong step's `attn_weights`/`v_states`.

Fixed by accumulating: `storage[layer_idx]` is now a list, one entry
appended per forward (index 0 = prefill, 1..N = decode steps in order).
Also fixed a related pairing bug: the `v_proj` forward hook fires *inside*
the attention module's own forward (before its post-forward hook runs), so
writing directly into `storage[layer_idx]["v_states"]` was writing into the
*previous* forward's dict, not the current one. Replaced with a `pending_v`
handoff dict: `v_hook_fn` stashes `pending_v[layer_idx] = v_states`, and the
attention module's own hook pops it (`pending_v.pop(layer_idx, None)`) when
building that forward's entry — this pairs correctly regardless of hook
registration order, relying only on the guaranteed nesting order (v_proj is
called from inside `attention.forward()`).

### 2b. `LocalModel.generate()` aggregates both phases (`agent/hf_local/runtime.py`)

With per-forward captures available, decode-step forwards only ever project
the *new* token (KV caching), so three helpers reassemble the full
picture from the accumulated list:

- `_concat_v_states(entries)` — concatenates every forward's `v_states`
  along the sequence dim (prefill's full-prompt V + each decode step's
  single-token V) into the full key/value sequence.
- `_build_square_attn(entries)` — builds a `(1, n_q, full_seq_len,
  full_seq_len)` causal attention matrix: the prefill entry fills its
  `(prompt_len, prompt_len)` block, each decode entry fills one row at its
  absolute position; not-yet-existing key columns stay zero, which is
  exactly what causal masking already implies.
- `_concat_block_outputs(all_steps, layer_idx)` — concatenates
  `output.hidden_states[step][layer_idx+1]` across all steps (prefill +
  decode) into the matching full-length residual-stream tensor.

`generate()` now calls `compute_probe_rows(..., phase="decode",
decode_window=...)` with this reassembled full-sequence capture whenever at
least one decode step happened (`len(all_steps) > 1`), in addition to the
existing `phase="prefill"` call. This exercises the causal
`A_q @ V_k_full` matmul path in `kv_probe.py` (fixed in bug #3 of the prior
session) with real windowed data instead of never running it. `probe_rows`
now contains `phase="decode"` rows with `seq_pos` set to each window's
start, as required.
